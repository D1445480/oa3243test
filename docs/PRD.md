# 產品需求文件 (PRD) - 校園活動資訊整合平台

## 1. 專案概述

### 背景與動機
目前大學校園中的活動資訊相當分散，包含講座、社團招生、學術競賽、校內工讀或行政公告等。這些資訊往往散落在學校官網、各系所網站、Facebook/Instagram 等社群平台、LINE 群組或實體海報上。
這導致學生需要花費大量時間在不同的管道間搜尋資訊，且容易因為漏看訊息而錯過心儀的活動。同時，校內活動的主辦單位（如社團幹部、系學會、處室等）也面臨宣傳管道不集中、曝光度不足的痛點。
因此，本專案旨在建立一個「校園活動資訊整合平台」，集中管理各類校園活動，提供清楚的分類、搜尋與瀏覽功能，並提供活動收藏與主辦單位自主發布/管理活動的功能，以提升資訊流動效率與活動參與率。

### 目標用戶
1. **一般學生**：希望快速瀏覽、搜尋、分類篩選並收藏感興趣的校園活動。
2. **社團幹部 / 系學會成員 / 校內活動主辦單位**：需要一個集中且高曝光的平台來發布、編輯與管理自己的活動資訊。

### 核心價值主張
- **資訊集中化**：一站式瀏覽所有校園活動，減少資訊搜尋成本。
- **自主發布與管理**：賦予主辦單位自主更新活動資訊的能力，確保資訊即時性。
- **個人化收藏**：學生可儲存感興趣的活動，方便追蹤與管理個人行程。

## 2. 功能需求

本系統的核心功能需求如下：

### 功能 1：使用者認證與角色管理 (User Authentication & Roles)
*   **說明**：提供使用者註冊、登入與登出功能，並區分角色（一般學生、活動主辦單位）。
*   **使用者故事**：
    *   作為**一般學生**，我希望能夠註冊並登入帳號，以便使用活動收藏與個人化清單功能。
    *   作為**活動主辦單位**，我希望能夠註冊為專屬帳號，以便獲得發布與管理活動的權限。

### 功能 2：活動瀏覽與搜尋 (Event Browsing & Search)
*   **說明**：提供所有使用者（包含未登入訪客）瀏覽活動列表、檢視活動詳情，並可依分類（如講座、社團活動、競賽、工讀、公告）與關鍵字進行搜尋和篩選。
*   **使用者故事**：
    *   作為**一般學生**，我希望能夠在首頁看到最新的活動列表，並依分類與關鍵字搜尋，以便快速找到感興趣的活動。
    *   作為**一般學生**，我希望點擊活動時能看到詳細資訊（時間、地點、主辦單位、詳細描述、聯絡資訊），以便決定是否參加。

### 功能 3：活動收藏功能 (Event Favorite / Bookmark) 【主要分工功能】
*   **說明**：已登入的學生使用者可將特定活動加入收藏，並可在「我的收藏」頁面集中查看所有已收藏的活動，亦可隨時取消收藏。
*   **使用者故事**：
    *   作為**一般學生**，我希望在瀏覽活動時點擊「收藏」按鈕，以便將活動暫存起來，避免日後找不到。
    *   作為**一般學生**，我希望能在個人專區的「我的收藏」頁面中，一目了然地看到所有已收藏活動的日期與時間，以便規劃個人日程。
    *   作為**一般學生**，我希望能在活動過期或失去興趣時，隨時在收藏頁面或活動詳情頁面「取消收藏」。

### 功能 4：活動發布功能 (Event Publishing) 【主要分工功能】
*   **說明**：已登入的活動主辦單位可填寫表單發布新活動，欄位包含活動名稱、分類、開始/結束時間、地點、活動描述、報名連結與聯絡方式等。
*   **使用者故事**：
    *   作為**活動主辦單位**，我希望能夠在平台上填寫活動詳情表單並發布，以便向全校學生宣傳我們的活動。
    *   作為**活動主辦單位**，我希望發布時可以為活動選擇合適的分類，以便目標學生能更容易篩選到該活動。

### 功能 5：活動管理功能 (Event Management) 【主要分工功能】
*   **說明**：主辦單位可以檢視自己發布的所有活動列表，並能對其進行編輯修改（更新時間、地點等最新資訊）或刪除/下架。
*   **使用者故事**：
    *   作為**活動主辦單位**，我希望能在「我發布的活動」專區中，查看自己發布過的所有活動。
    *   作為**活動主辦單位**，當活動資訊有變更（例如改期或換教室）時，我希望能夠直接編輯該活動，以便學生看到最新的資訊。
    *   作為**活動主辦單位**，當活動因故取消時，我希望能夠刪除或下架該活動，以避免學生跑錯。

## 3. 非功能需求

### 技術限制
*   **後端框架**：Flask (Python 3.x)
*   **前端模板**：Jinja2 + HTML / CSS / JavaScript (原生為主，具備良好的響應式設計)
*   **資料庫**：SQLite

### 效能與安全考量
*   **資料安全性**：
    *   使用者密碼必須經過雜湊加密儲存（如使用 Werkzeug 提供的 `generate_password_hash` 與 `check_password_hash`）。
    *   必須實作 Session 機制，確保使用者無法越權存取其他主辦單位的活動管理頁面。
*   **使用者體驗 (UX)**：
    *   介面需支援響應式網頁設計 (RWD)，確保在手機與桌上型電腦皆有良好的閱讀體驗。
    *   操作回饋：如收藏成功、發布成功時需有明確的提示訊息（Flash Messages）。

為了確保專案順利推進，以下劃分 MVP 範圍：

| 功能優先級 | 功能名稱 | 描述 |
| :--- | :--- | :--- |

| | **活動收藏功能** | 學生可收藏活動並在「我的收藏」清單中查看。 |

## 6. 驗證與測試計畫

### 6.1 功能測試 (Functional Testing)
*   **註冊與登入**：驗證一般學生與主辦單位帳號註冊與登入流程是否正確導入對應頁面。
*   **發布活動**：主辦單位帳號新增活動後，確認首頁與資料庫能正確即時更新。
*   **活動管理**：
    *   主辦單位編輯活動，確認修改內容能正確呈現。
    *   主辦單位刪除活動，確認該活動從首頁與資料庫中消失。
    *   非該活動主辦單位帳號，應無法透過直接輸入 URL 編輯或刪除該活動。
*   **活動收藏**：
    *   一般學生點擊收藏後，確認「我的收藏」頁面出現該活動。
    *   在「我的收藏」點擊取消，確認活動被移除。
    *   未登入使用者點擊收藏，系統應引導至登入頁面。

### 6.2 介面與相容性測試 (UI & Compatibility)
*   使用瀏覽器開發者工具模擬不同手機尺寸（如 iPhone, Android 裝置），確保版面無跑版、按鈕好點擊。
